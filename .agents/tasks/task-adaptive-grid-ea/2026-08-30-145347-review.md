# Recovery-engine remediation: net break-even, per-side level index, and averaging throttle (v2)

Second-pass review of commit `e54bed6`, which addresses the five issues raised in v1 of the adaptive gold grid + bounded-martingale recovery EA. The remediation is confined to three modules — `OrderManager.mqh` (new `CountSidePositions`/`SideVolume`/`NetBasketBreakEven` helpers, `IsTradeContextFree` hardening), `LotSizer.mqh` (exposure-cap rounding fix, documented tick-value assumption), and `RecoveryEngine.mqh` (net break-even in points-mode TP, per-recovery-side level index, anti-restack throttle). The EA, SafetyValve, MarketAnalysis, GridEngine geometry, MLHook, and README are untouched, so the v1 conclusions about those paths carry forward unchanged. No compiler/MT5 is available here, so this remains a by-inspection review.

Watch for: nothing blocking. All five v1 issues are resolved by inspection and the critical safety invariant is intact — the only close path is still the profit-gated `CloseBasket()`, and every new construct (net break-even, side-level count, spacing throttle) either computes a target or throttles an *entry*, never realizes a loss and never halts. One minor observation (**possible**): the averaging throttle stamps on *proposal* rather than on *fill*, so a rejected send delays the next add by a bar — this fails toward holding and is safe, worth a mention only so the behavior is understood.

**Verdict**: APPROVED

## High-level view

The safety contract is preserved. The remediation added target math and entry throttles only; a full-source scan confirms `PositionClose` still appears solely inside `CloseBasket()`, reached only from the `pnl > 0`-gated group-TP branch, and there is no `ExpertRemove` or position-modify anywhere. Nothing in the new code opens a loss-realizing path.

The points-mode TP after a hedge (v1 issue #1) now branches on basket shape: a one-sided basket uses the side's weighted-average entry as before, while a genuinely hedged basket nets both legs through `NetBasketBreakEven`, which solves for the price where combined buy/sell P&L is zero. A netted-flat basket (net exposure below half a volume step) returns `ok=false` and the points check bails, deferring to the `pnl > 0` guard — the correct fail-safe, since no single price defines break-even for a flat book.

The martingale level index (v1 issue #2) is now `CountSidePositions(dir)` — positions on the recovery side only — for both averaging and the hedge leg, so an opposite-side hedge no longer inflates the `factor^level` exponent or eats into `max_grid_levels`. Signatures line up: `RecoveryLot` and `BuildNextLevelIntent` both take the level as their trailing `int`, and the hedge is sized at its own side's level.

The averaging restack risk (v1 issue #3) is now bounded by an explicit throttle requiring both a new bar and price at least one adaptive step beyond the last add, cleared in `ResetBasketState`. The exposure-cap rounding leak (v1 issue #4) is closed by returning 0 when remaining room is below the broker volume minimum, before normalization can round up. The tick-value assumption (v1 issue #5) is now documented in place with a backtest-verification note; the pre-existing zero/invalid guard is retained.

### Net break-even correctly generalizes the one-sided case

`NetBasketBreakEven(net_dir, ok)` solves `(price - buy_avg)*buy_vol - (price - sell_avg)*sell_vol = 0` for price, giving `(buy_avg*buy_vol - sell_avg*sell_vol) / (buy_vol - sell_vol)` — the price at which the combined book's floating P&L crosses zero, which is what a points-from-break-even target needs once both legs are open. It returns `ok=false` when `|net_lots|` is below half a volume step (a netted-flat book has no single break-even price), and sanity-checks that the net side matches the requested `net_dir` so a caller can't measure the target against the wrong direction.

The `GroupTargetReached` call site gates on `have_buy && have_sell`, both derived from `WeightedAvgEntry(side) > 0`, which returns 0 for an empty side, so the hedged-vs-one-sided detection is exact. When the net helper returns `ok=false`, the points branch returns `false` and the basket holds; currency-mode TP, which sums both legs via `BasketFloatingPnL`, still handles netted baskets correctly. No branch here can trigger a close on its own — the terminal `pnl > 0` guard is still in force below the target-price comparison.

### Per-side level index no longer conflated with total basket count

```
int side_level  = m_om.CountSidePositions(dir);        // averaging
int hedge_level = m_om.CountSidePositions(hedge_dir);  // hedge leg
```

`CountSidePositions` filters by magic + symbol + position type, so it counts only the leg being extended. Both `RecoveryLot(mc, dir, side_level)` and `BuildNextLevelIntent(mc, dir, avg, side_level)` receive this per-side count, and `BuildNextLevelIntent`'s `current_levels >= max_grid_levels` ceiling now trips on recovery-side depth rather than total basket size — so a hedge leg neither inflates `base_lot * factor^level` nor prematurely exhausts grid depth. The hedge itself is sized at `hedge_dir`'s own level (0 on first placement, since the hedge side is empty until then), which is the seed-level bounded lot the v1 code was reaching for with the hardcoded `0`. Signatures match across `LotSizer`, `GridEngine`, and `OrderManager`; no arity or type mismatch.

### Averaging throttle is deterministic and entry-only

`AveragingSpacingOK` allows the first add unconditionally (no prior stamp), then requires both a new bar (`bar != m_last_add_bar`) and price at least one `AdaptiveStepPoints` beyond `m_last_add_price` in the adverse direction. Combined with the existing `PriceMovedOneStepAdverse` trigger, adds are now spaced by at least one bar and one adaptive step regardless of how fast price moves within a bar — closing the v1 gap where several levels could stack in one bar before the weighted average caught up. The stamp is cleared in `ResetBasketState`, so a fresh basket starts clean.

The behavioral nuance: `StampAveragingAdd(gi.price)` fires at proposal time, inside `Manage`, before the main EA runs the SafetyValve gate and sends. If the send is later rejected (margin, context, broker), the stamp is still set, so the next add waits for a new bar rather than retrying on the next tick. This delays recovery adds under adverse conditions but never forces a close and never realizes a loss — it fails toward the "hold" state the system is built around. (The `m_grid==NULL` early-return-true inside the helper is inert because the averaging block already guards `m_grid!=NULL` before calling it.)

### Exposure-cap rounding leak closed

`ApplyBounds` now reads `SYMBOL_VOLUME_MIN` and returns `0.0` when `room < vmin`, before the `NormalizeLot` call that would otherwise round a sub-minimum remainder up past `max_basket_exposure_lots`. This makes the total-exposure ceiling strict at the boundary, on the "return 0 = cannot add = hold" path — so it tightens the cap and pushes toward holding.

### Tick-value assumption documented; guard retained

`SeedLot` now carries an explicit block explaining that gold tick value/size vary by broker (per-ounce vs per-100-oz-contract, plus account-currency conversion) and that the ATR-stop notional should be verified in the Strategy Tester before going live. The math can't be validated without a specific broker's contract specs, so documenting the assumption and keeping the `tick_value > 0 && tick_size > 0` fallback to `base_lot` is the right disposition for what was a `possible`-confidence v1 note.

### IsTradeContextFree hardening

`IsTradeContextFree` now returns false when either `IsStopped()` or `!TerminalInfoInteger(TERMINAL_TRADE_ALLOWED)`, addressing the v1 note that the helper's name overstated what it checked. It remains read-only and never closes or forces anything.

### Invariant re-confirmation

A full-source grep for `ExpertRemove`, `PositionClose`, `OrderClose`, and `PositionModify` finds `PositionClose` only inside `CloseBasket()`/`ClosePartial()`; `ClosePartial` has no caller, and `CloseBasket()` is invoked from exactly one site — the `GroupTargetReached`-gated branch in `Manage`, itself guarded by `pnl > 0` in both TP modes. `SafetyValve` still contains no close/halt of any kind. None of the v2 additions introduce a new close, halt, or position modification: `NetBasketBreakEven` and the points-mode branch only compute and compare a target price; `CountSidePositions`/`SideVolume` only count; the throttle only blocks entries; the `ApplyBounds` change only returns a smaller (or zero) lot. The bounded-martingale choke point (`ApplyBounds`), adaptive spacing, honest classical-vs-ML labelling, and README accuracy all remain as verified in v1, since those files were not touched by this commit.
